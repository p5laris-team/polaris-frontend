## 1. 운영 원칙

이스터에그는 사용자를 놀라게 하되, 핵심 행동을 방해하면 안 된다.

- 보상이나 재화 지급과 직접 연결하지 않는다.
- 사용자를 비난하거나 실패감을 주는 문구를 피한다.
- 반복 노출 시 피로하지 않게 하루 노출 횟수를 제한한다.
- 캐릭터 성격과 말투를 지킨다.
- 접근성 설정 또는 저성능 기기에서는 정적 문구로 대체할 수 있어야 한다.

## 5. 주의할 이스터에그

| 후보 | 위험 | 처리 |
|---|---|---|
| 미션 15개 모두 거절 시 삐짐 | 사용자에게 죄책감을 줄 수 있음 | 장난스럽지만 위로 중심으로 표현 |
| 밤 늦게 접속 시 경고 | 생활 패턴 비난처럼 보일 수 있음 | 권유형 문구만 사용 |
| 별조각 보유량 기반 문구 | 경제 행동 유도처럼 보일 수 있음 | 구매 유도 없이 축하만 |
| 연속 출석 끊김 | 실패감 유발 | 언급하지 않음 |

권장 문구:

```text
오늘은 여기까지 봐도 괜찮아요. 내일 또 다른 별이 올 거예요.
```

피해야 할 문구:

```text
오늘 미션을 너무 많이 거절했어요.
```

## 6. 구현/분석 기준

구현 기준:

- 이스터에그 상태는 서버 저장 없이 클라이언트 로컬로 시작해도 된다.
- 단, 보상 지급/아이템 unlock이 연결되면 서버 정책이 필요하다.
- MVP에서는 toast 또는 말풍선 문구만 사용하고, 재화 지급은 하지 않는다.

분석 이벤트 후보:

| 이벤트 | 속성 |
|---|---|
| `easter_egg_seen` | type, characterType, route |
| `character_tap_burst` | tapCount, durationMs |
| `special_dialog_seen` | dialogKey, characterType |
