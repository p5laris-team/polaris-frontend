## 1. 원칙

Polaris의 애니메이션은 사용자를 재촉하기보다 작은 행동을 인정해주는 방향이어야 한다.

- 1회 애니메이션은 300~1400ms 안에서 끝낸다.
- 루프 모션은 2초 이상 간격을 둔다.
- 보상/완료/장착처럼 의미 있는 순간에만 강한 연출을 쓴다.
- 입력 중인 화면에서는 배경 모션을 줄인다.
- reduced motion 설정을 반드시 존중한다.

## 4. 화면별 설계

### 홈

| 트리거 | 반응 |
|---|---|
| 캐릭터 탭 1회 | 캐릭터가 살짝 통통 움직임 |
| 캐릭터 탭 3회 | 짧은 대사 노출 |
| 상태 BAD | 상태 게이지와 캐릭터 자세가 함께 약하게 변함 |
| 홈 진입 | 캐릭터 idle 모션 1회 |

### 미션

| 트리거 | 반응 |
|---|---|
| 미션 완료 버튼 | 질문 화면으로 전환 전 버튼 loading |
| 완료 답변 제출 | 별조각 파티클, happy 이미지 |
| 미션 거절 | 다음 미션 카드가 부드럽게 교체 |
| 하루 15개 소진 | 과한 실패 연출 없이 오늘 종료 안내 |

### 캐릭터 돌봄

| 트리거 | 반응 |
|---|---|
| 밥 주기 | 포만감 게이지 상승, 캐릭터 밝아짐 |
| 재우기 | 기운 게이지 상승, 졸림에서 회복 |
| 놀아주기 | 애정 게이지 상승, 작은 반짝임 |

### 상점/보관함

| 트리거 | 반응 |
|---|---|
| 구매 성공 | 별조각 감소 숫자 강조 |
| 별조각 부족 | 버튼 흔들림 대신 toast 안내 |
| 장착 성공 | 장착 카드 border glow |
| 기본 외형 해제 | 차분한 reset 전환 |

### 공유 카드

| 트리거 | 반응 |
|---|---|
| 메시지 선택 | 카드 문구 즉시 반영 |
| 카드 생성 | 링크 카드 slide-in |
| 공유 보상 지급 | 보상 배너 완료 상태로 전환 |

## 5. 캐릭터 탭 반응

탭 반응은 홈 화면에서만 우선 적용한다.

| 조건 | 반응 | 예시 대사 |
|---|---|---|
| 1회 탭 | 살짝 움직임 | 없음 |
| 3초 안에 3회 | 말풍선 대사 | "무... 나 불렀어요?" |
| 5초 안에 5회 | 이스터에그 대사 | "오늘 관심 많이 받는 날이네요." |
| 밤 12시 이후 3회 | 졸린 대사 | "무... 이제 잘 시간일지도요." |

주의:

- 탭 반응은 미션 카드 CTA를 방해하면 안 된다.
- 5회 탭 이스터에그는 하루 1~2회만 노출한다.
- 캐릭터 상태 BAD일 때는 장난스러운 반응보다 돌봄 유도 대사를 우선한다.

## 6. 접근성/reduced motion

`prefers-reduced-motion: reduce` 환경에서는 다음 원칙을 따른다.

- 파티클 이동을 제거하고 opacity 전환만 사용한다.
- 무한 루프 모션을 정지 이미지로 대체한다.
- 흔들림/점프/스케일 애니메이션을 최소화한다.
- 보상 결과는 시각 연출 없이 텍스트와 숫자로 전달한다.

권장 CSS:

```css
@media (prefers-reduced-motion: reduce) {
  * {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

## 7. 구현 체크리스트

- [ ] 애니메이션은 기능 성공/실패 상태와 연결된다.
- [ ] 클릭 후 상태 변화가 100ms 안에 시작된다.
- [ ] 토스트와 애니메이션 메시지가 서로 충돌하지 않는다.
- [ ] 같은 화면에서 동시에 2개 이상의 강한 애니메이션이 나오지 않는다.
- [ ] reduced motion 환경에서 정보 손실이 없다.
- [ ] CSS-only로 가능한 것은 CSS로 먼저 구현한다.
- [ ] Lottie/Rive 도입은 파일 크기와 런타임 성능 확인 후 결정한다.
