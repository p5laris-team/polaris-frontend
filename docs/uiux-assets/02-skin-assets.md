## 1. 스킨 정책

MVP 실제 정책은 스킨만 둔다.

- 액세서리 장착은 MVP 제외
- 배경 장착은 MVP 제외
- 광고 슬롯은 MVP 제외
- 스킨은 캐릭터 외형을 교체하는 단위
- 스킨은 한 번에 하나만 장착
- `itemId: null`이면 기본 외형으로 해제
- 장착 여부는 클라이언트가 캐릭터의 `equippedSkin.itemId`와 보유 아이템 `itemId`를 비교해 판단

정책 문구:

```text
스킨은 캐릭터의 전체 외형 테마를 바꾸는 아이템이다.
액세서리처럼 슬롯별로 조합하지 않는다.
```

## 2. 스킨 에셋 매트릭스

| 에셋 | 사용 화면 | P0 필요 여부 | 설명 |
|---|---|---:|---|
| 상점 썸네일 | SCR-013 상점 | 필요 | 구매 전 카드 |
| 보관함 썸네일 | SCR-014 보관함 | 필요 | 보유 목록 |
| 장착 프리뷰 | SCR-006 홈, SCR-012 캐릭터 | 필요 | 실제 외형 |
| 공유 카드 이미지 | SCR-016 공유 | 필요 | 카드 중앙 이미지 |
| 상태별 idle/happy/sleepy | 홈, 결과, 공유 | P1 | 장착 스킨 상태 반영 |
| 구매 완료 연출 | 상점 | P1 | 반짝 전환 |
| 장착 완료 연출 | 보관함 | P1 | 기본 외형에서 스킨으로 전환 |

## 3. MVP 스킨 후보

| 스킨 | 컨셉 | 권장 가격 | 표현 포인트 |
|---|---|---:|---|
| 말랑 별빛 스킨 | 부드러운 별빛, 따뜻한 색감 | 60 | 초보자 첫 구매에 적합 |
| 은은한 새벽 스킨 | 차분한 파랑/민트, 새벽 루틴 | 70 | 노바와 잘 맞음 |
| 밤하늘 스킨 | 깊은 남색, 작은 별 패턴 | 80 | 공유 카드에서 대비 좋음 |

스킨별 제작 시 주의:

- 캐릭터 고유 실루엣을 덮어버리면 안 된다.
- 스킨 이름만 보고도 분위기가 떠올라야 한다.
- 상점 카드에서 작은 썸네일로 보여도 차이가 드러나야 한다.
- 같은 스킨이 노바/무무/쪼리에게 적용될 때 캐릭터별 체형 차이를 반영한다.

## 4. 스킨별 상태 대응

MVP 최소:

```text
skin-{skinKey}-{characterKey}-idle.png
```

P1 권장:

```text
skin-{skinKey}-{characterKey}-idle.png
skin-{skinKey}-{characterKey}-happy.png
skin-{skinKey}-{characterKey}-sleepy.png
```

상태별 방향:

| 상태 | 스킨 표현 |
|---|---|
| idle | 스킨의 기본 매력이 가장 잘 보이는 포즈 |
| happy | 스킨 소재/패턴에 작은 반짝임 추가 |
| sleepy | 색 대비를 줄이고 눈/자세로 졸림 표현 |
| bad 상태 | 스킨 효과보다 캐릭터 상태가 먼저 읽히게 표현 |

## 5. 상점/보관함 표현

상점 카드:

- 스킨 이름
- 가격
- 미보유/보유/구매 가능/별조각 부족 상태
- 썸네일
- 구매 버튼

보관함 카드:

- 스킨 이름
- 장착 중 표시
- 장착하기 버튼
- 기본 외형으로 해제 카드

기본 외형 카드:

```text
기본 외형
스킨을 해제하고 원래 모습으로 돌아가요.
```

## 6. 검수 체크리스트

- [ ] 스킨이 액세서리처럼 보이지 않고 전체 외형 테마로 보인다.
- [ ] 상점 썸네일과 장착 프리뷰가 같은 스킨임을 쉽게 알 수 있다.
- [ ] 기본 외형 해제 상태가 명확하다.
- [ ] 노바/무무/쪼리 모두에서 스킨 컨셉이 유지된다.
- [ ] 공유 카드에서도 스킨이 잘 보인다.
- [ ] 스킨별 파일명과 API item id 매핑이 문서화되어 있다.
